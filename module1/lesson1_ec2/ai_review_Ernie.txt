Q2: When running legacy COBOL programs like payment_post or account_lookup, what is the functional difference between receiving a return code of 4 versus a return code of 8?

Q3: Why is it necessary to open a second SSH terminal window in Step 5 before running commands like curl [http://127.0.0.1:8000/status](http://127.0.0.1:8000/status) or executing the SWIFT traffic generator script? How can I test this?

AI's answer, in my own words: When a process runs in the foreground, it takes full control of the terminal session and does not allow any other process to run in that terminal or other commands to be initiated. If you press Ctrl-C you will gain control of the terminal but stop the process you need. Therefore, you need to keep that process running and execute your other commands in a separate terminal session.

How I checked it: This was done as part of the runbook where we started the uvicorn session and had to open a separate terminal windoow to enter additional commands to interacti with the server.


Q4: In the fixed-width ledger file (data/accounts.dat), how is a balance represented across columns 45–56, and why does a raw value like 000000012550 translate to 125.50?

AI's answer, in my own words: COBOL uses the picture clause PIC 9(10)V99. PIC 9(10) in the field width to allocate 10 digits for the integer and V99 to allocate 2 digits for the decimal places. COBOL stores monetary values with implied decimals in order to save storage and simplify processing.

How I checked it: I ran 2 commands to show how the monetary values were displayed and parsed. When I posted a payment of 125.99 it was stored in the data/payments.dat file as 100001000000012599USDPOSTED showing that the decimal point was stripped when written to the fixed-width file.
